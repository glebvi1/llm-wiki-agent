# Telegram → LLM Wiki

Локальная интеграция личного Telegram с LLM Wiki и Codex. Работает на компьютере владельца аккаунта, не использует Telegram-бота и не передаёт сессию в Wiki или Git.

## Что реализовано

- Подключённые и неподключённые чаты показываются отдельно. В обоих разделах работают поиск и фильтры по типу чата. При подключении можно выбрать глубину импорта и добавить комментарий. Комментарий сохраняется при отключении и учитывается с начала следующего разбора.
- Порционная догрузка истории, повторный импорт без дублей, учёт правок и доступных удалений. Неизменяемые JSON и Markdown-порции сохраняются в `Исходники/Telegram/`.
- Пока приложение запущено, оно проверяет выбранные чаты раз в минуту. Codex обрабатывает сохранённые сообщения ежедневно в 09:00 по Москве. Кнопка «Обновить сейчас» запускает оба шага вне расписания.
- Скилл `wiki-telegram-ingest` обновляет только связанные страницы Wiki, различает факты и предложения, сохраняет основания и вопросы. До явного принятия его версии автоматические правки Wiki запрещены.
- Один вопрос с одной служебной задачей в Tracker; ответ принимается из карточки или однозначно связанного чата Codex.
- Разовое чтение любого доступного чата не включает импорт и не пишет источники Wiki.
- Черновик не отправляется и не затирает существующий без подтверждения. Сообщение отправляется только после подготовки точного текста и адресата, их показа и отдельной явной команды. Повтор после обрыва использует стабильный Telegram `random_id` и сначала проверяет историю.
- Удаление сохранённых источников требует ввода `УДАЛИТЬ` и заранее показывает связанные страницы; сами страницы Wiki автоматически не удаляются.

Первая версия не скачивает вложения, не транскрибирует аудио и не отправляет сообщения в каналы.

## Инструменты MCP

| Инструмент | Что делает |
| --- | --- |
| `list_chats` | Находит чат по названию, имени пользователя или ID. Показывает, включён ли импорт. |
| `read_messages` | Читает свежие сообщения по ID чата. Можно искать по словам и ограничить период. |
| `get_message_context` | Показывает сообщения вокруг выбранного сообщения и доступную связь ответа. |
| `get_drafts` | Читает текущие черновики. |
| `save_draft` | Сохраняет черновик без отправки. Для замены существующего черновика нужно явное согласие пользователя. |
| `prepare_send` | Фиксирует адресата и точный текст, возвращает `approvalId`. |
| `send_prepared` | Отправляет подготовленное сообщение после явной команды пользователя. Сервер сверяет параметры с подготовленной операцией. |
| `ingest_status` | Показывает, принят ли скилл, какие порции ждут разбора и остались ли открытые вопросы. |
| `ingest_begin` | Фиксирует порции и настройки чатов для разбора или продолжает начатый проход. |
| `ingest_finish` | Завершает проход по переданному итогу после проверки файлов и вопросов. |

[Схемы параметров](src/server/mcp.ts#L84), [подготовка и отправка](src/server/operations.ts#L16), [импорт сообщений](src/server/importer.ts#L67) и [обработка порций для Wiki](src/server/processing.ts#L39).

## Требования

- Windows, Node.js 24 или новее, pnpm 11.
- [`uv`](https://docs.astral.sh/uv/) для закреплённого Python-окружения Telegram MCP.
- Codex CLI и существующая LLM Wiki с `AGENTS.md` и `Правила LLM Wiki.md`.
- API ID и API Hash личного приложения с `my.telegram.org/apps`. Это не токен бота.

## Установка и запуск

Запустите из корня репозитория, указав путь к своей Wiki:

```bash
npx --yes pnpm@11.7.0 --filter telegram-wiki run setup -- --wiki "D:\Wiki"
```

`setup` добавляет скилл и MCP в Wiki, создаёт ежедневное расписание Codex, ярлыки «Telegram в LLM Wiki» и задачу Windows для фонового запуска при входе. Перед изменениями установщик сохраняет копии в `.local/telegram-wiki/install-backup/`. Существующие MCP, токен и `approval.json` сохраняются. Чтобы пропустить настройку запуска Windows и ярлыков, добавьте `--no-startup`.

Дважды нажмите ярлык на рабочем столе или откройте «Telegram в LLM Wiki» из меню «Пуск». Интерфейс откроется в отдельном окне со своей иконкой на панели задач. После входа в Windows сервер запускается в фоне. Если он ещё не успел запуститься, ярлык запустит его и дождётся ответа. Журнал запуска лежит в `.runtime/start.log` рядом с приложением.

## Авторизация

Если API ID и API Hash ещё не сохранены на компьютере, один раз выполните `npx --yes pnpm@11.7.0 --filter telegram-wiki login`: команда интерактивно спросит их и покажет QR в терминале. Не отправляйте эти данные, QR или содержимое сессии в чат.

Когда ключи сохранены, вход и повторный вход после отзыва сессии выполняются кнопкой **«Авторизоваться»** в интерфейсе. Отсканируйте QR через «Telegram → Настройки → Устройства → Подключить устройство». Если включена двухфакторная аутентификация, введите пароль в поле на странице: он не сохраняется и не пишется в журнал. Кнопка **«Переподключить аккаунт»** доступна и после успешного входа.

После входа выберите чаты и глубину импорта. Проверьте скилл и явно примите его точную версию в Codex: установка и авторизация сами по себе таким принятием не являются.

Для разработки интерфейса:

```bash
npx --yes pnpm@11.7.0 --filter telegram-wiki dev -- --host 127.0.0.1 --port 7100
```

Режим `dev` использует `temp/wiki` или `TELEGRAM_WIKI_ROOT`, а не боевую Wiki. По умолчанию он не подключается к Telegram и не конкурирует за сессию с установленным приложением; для отладки подключения отдельно установите `ENABLE_TELEGRAM_GATEWAY=1`.

## Хранение

- `%APPDATA%\Gyromind\telegram-credentials.json` — API ID/hash.
- `%APPDATA%\Gyromind\telegram-account.session` — личная сессия Telegram.
- `%APPDATA%\Gyromind\telegram-wiki.json` — путь Wiki, локальный Bearer-токен и настройки подключения.
- `<Wiki>\.local\telegram-wiki\` — состояние синхронизации, обработки, подтверждений и резервные копии.
- `<Wiki>\Исходники\Telegram\` — неизменяемые исходные порции и сохранённые уточнения.

Сервисы слушают только `127.0.0.1`: Telegram MCP на порту 8765, интерфейс и узкий MCP для Codex на порту 7100. Исходный сторонний MCP не подключается к Codex напрямую.
